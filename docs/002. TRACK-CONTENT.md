# 002. Track content

This is the operational checklist for adding a Phase 1 track. A track is only listed in
the game once its source files, licence provenance, rendered audio and chart are all in
place.

The design that motivates this pipeline, including the verified Phase 1 shortlist, is
[`003. PHASE-1-DESIGN.md`](003.%20PHASE-1-DESIGN.md).

## Licence gate

Every track must be one of:

- **CC0 / public domain**, or
- **CC BY**, with the exact attribution text recorded.

Do not add a track whose licence is unclear, whose source URL is missing, or which is
CC BY-SA, non-commercial or no-derivatives. Phase 1 keeps those options open for
productisation. The catalogue stores licence metadata and the UI displays it.

Record, for each track:

- `licence` — the source composition/MIDI licence
- `audioLicence` — the rendered audio licence (Phase 1 renders are CC0)
- `attribution` — the exact credit line required by the source and soundfont
- `sourceUrl` — the page the source was obtained from
- `sourceSha256` — hash of the committed source MIDI

## Source layout

Use a stable lowercase track id, for example `ode-to-joy`.

```
content/
  SOUNDFONT-LICENSE.md
  tracks/<track-id>/
    track.json          # metadata, licence, difficulty, melody source
    source.mid          # full public-domain arrangement
    melody.mid          # audited melody voice only
    LICENSE.md          # provenance and attribution
```

`melody.mid` is the single source of truth for the chart. Create it from an explicit
source voice (Ode's `sop` voice, Twinkle's melody track, Greensleeves' `treble` track) or
from a manually reviewed extraction. Never generate a chart from a heuristic top voice
when the source has an explicit melody.

## Rendered output

The content script renders audio and charts into `public/`:

```
public/
  audio/<track-id>.backing.mp3   Melody muted
  audio/<track-id>.guide.mp3     Optional melody-only guide stem
  charts/<track-id>.json         Pre-computed note chart
```

Files in `public/` are served from the site root, so the catalogue paths are:

```ts
audioUrl: "/audio/ode-to-joy.backing.mp3",
guideUrl: "/audio/ode-to-joy.guide.mp3", // optional
chartUrl: "/charts/ode-to-joy.json",
```

MP3 is preferred because it is small and supported everywhere. The backing and guide
stems must start at the same sample and use the same tempo map. `durationSec` describes the
performance (the chart's musical length), not the MP3 file length including reverb tail.

## Chart format

Charts are generated ahead of time from `melody.mid` and verified against the backing
stem. They are not computed in the browser.

```json
{
  "version": 1,
  "trackId": "ode-to-joy",
  "sourceInstrument": "vocals",
  "tempoBpm": 100,
  "keySignature": "G major",
  "notes": [
    { "startSec": 0.0, "durationSec": 0.6, "midi": 71 },
    { "startSec": 0.6, "durationSec": 0.6, "midi": 71 },
    { "startSec": 1.2, "durationSec": 0.6, "midi": 72 }
  ]
}
```

Field rules:

- `startSec` and `durationSec` are seconds from the start of the backing audio, not beats.
- `midi` is the sounding reference pitch. Range fitting happens at play time.
- `lyric` is optional; omit it until lyric timing is designed.
- Notes must be sorted by `startSec` and must not overlap.
- Notes shorter than 80 ms are dropped; repeated identical pitches separated by less than
  50 ms are merged.

The current base type is `TrackChart` in [`src/shared/domain.ts`](../src/shared/domain.ts).
M1 adds `version`, `keySignature` and the optional guide URL to the catalogue and chart
types.

## Adding the catalogue entry

Do not hand-edit the catalogue. Add `content/tracks/<track-id>/track.json` and run the
content build/validate scripts; they generate the `TrackSummary` entries consumed by the
Worker.

```json
{
  "id": "ode-to-joy",
  "title": "Ode to Joy",
  "artist": "Ludwig van Beethoven",
  "difficulty": "medium",
  "licence": "Public domain",
  "audioLicence": "CC0 1.0",
  "attribution": "Composition: Ludwig van Beethoven. MIDI: Mutopia Project (public domain).",
  "sourceUrl": "https://www.mutopiaproject.org/cgibin/piece-info.cgi?id=528",
  "sourceMidi": "source.mid",
  "sourceSha256": "<hash>",
  "soundfont": "FluidR3Mono_GM (MIT)",
  "melody": { "source": "melody.mid", "voice": "soprano" },
  "audio": {
    "backing": "/audio/ode-to-joy.backing.mp3",
    "guide": "/audio/ode-to-joy.guide.mp3",
    "durationSec": 38.4
  },
  "chart": "/charts/ode-to-joy.json",
  "keySignature": "G major",
  "tempoBpm": 100
}
```

## Verification checklist

- [ ] Licence permits use, redistribution and derivative charts; attribution and source
  URL are recorded.
- [ ] Source MIDI hash matches `track.json`.
- [ ] `melody.mid` matches the intended voice and the audible/score reference.
- [ ] Backing and guide stems start together and align with the chart.
- [ ] Audio decodes in Chrome, Safari and Firefox.
- [ ] `durationSec` matches the chart's musical end, and the backing file is at least that
  long.
- [ ] Chart note count and first/last note timings line up with the audible melody.
- [ ] Every note is inside the chosen source instrument's written range.
- [ ] Chart file is valid JSON and parses as `TrackChart`.
- [ ] `npm run content:validate` passes.
- [ ] Catalogue entry loads through `GET /api/tracks`.
- [ ] Setup screen displays the track, duration, licence and guide toggle.
- [ ] A human plays along once and confirms the target notes are the melody they hear.
